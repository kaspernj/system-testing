Replace the single input-replacement helper with three orthogonal methods — `clear(target, {strategy, keyDelay})`, `fill(target, value, {strategy, keyDelay})` (pure fill, does not clear first), and `clearAndFill(target, value, {clearStrategy, fillStrategy, keyDelay})`. Each defaults to a fast strategy: `clear` uses a native Selenium `element.clear()`, `fill` uses one whole-string `element.sendKeys(value)`. Slow keyboard strategies (`backspace-keys`/`delete-keys` clear, `per-character` fill) and the `js` DOM value-setter escape hatch (also the `replaceValueWithJs` interact method) are explicit opt-in overrides; `keyDelay` configures the pause between key presses. `clearAndSendKeys` stays as a thin convenience alias of `clearAndFill` with fast native defaults so existing call sites keep working while they migrate. Remove the silent `withFallback` sendKeys DOM value-setter fallback outright (pre-release, no compat). Flaky clearing/typing is a controlled-input smell — the real fix is an uncontrolled input, documented in the README "Clearing and filling inputs" section.
